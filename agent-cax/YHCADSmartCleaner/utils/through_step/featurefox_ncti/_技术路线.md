## 1. TL;DR

> **featurefox_ncti = FeatureFox 论文思路 + NCTI 原生数据 + 团队特征工程的两级 XGBoost 分类器**
>
> **目标**：在 NCTI 环境下自动识别 CAD 零件里的"通槽"特征
>
> **当前水平**：F1 = 83.4%（vs 规则方法 53%），在 62495 件合成件上验证
>
> **下一阶段重点**：
> 1. 第二级扩为 **24 类 Panoptic**（一份模型干 5+ 件事）
> 2. 真实工业件微调（解决 domain gap）
> 3. 评估指标升级为 **PQ**（与 FeatureFox 论文对齐）
>
> ⚠️ **关键澄清**：30 维 / 26 维特征**不是 FeatureFox 论文的精确复现**。FeatureFox 论文**不公开代码与数据**（公司机密政策），团队特征是**混合借鉴 + 领域扩展**。详见 [§5 特征来源拆解](#5-特征来源拆解)。

## 2. 数据流管线总览

### 2.1 端到端架构图

```
┌────────────────────────────────────────────────────────────────────────┐
│  输入：STEP 文件（CAD 几何）                                              │
└───────────────────────────────────┬────────────────────────────────────┘
                                    ↓
┌────────────────────────────────────────────────────────────────────────┐
│  NCTI 导入（约定 A）                                                    │
│  ──────────────────                                                    │
│  doc.New("OCC","DCM",0) → RunCommand("cmd_ncti_import_file", ...)      │
│  代码：[ncti_backend.py:load_part()](YHCADSmartCleaner/utils/through_step/featurefox_ncti/ncti_backend.py)│
│                                                                        │
│  拿到：                                                                 │
│  - ai.FaceAttr[i]   12 维（每面）                                       │
│  - ai.EdgeAttr[i]   10 维（每边）                                       │
│  - ai.FaceEID / FaceFID  （边连接的两个面）                                │
│  - ai.FaceID        （面 ID 列表）                                       │
└───────────────────────────────────┬────────────────────────────────────┘
                                    ↓
┌────────────────────────────────────────────────────────────────────────┐
│  NctiPart 后端封装                                                      │
│  ─────────────────                                                      │
│  代码：[ncti_backend.py:NctiPart](YHCADSmartCleaner/utils/through_step/featurefox_ncti/ncti_backend.py)│
│                                                                        │
│  整理出 4 张边表：                                                       │
│  - adjacency[cell] → set(相邻 cell)                                    │
│  - edge_convexity[(min,max)] → concave/convex/smooth/unknown            │
│  - edge_dihedral[(min,max)] → 连续符号值                                │
│  - edge_length_map[(min,max)] → 累加长度                                │
│  - edge_type[(min,max)] → line/circle/other                              │
│                                                                        │
│  几何查询（UV 中心采样）：                                                 │
│  - face_normal(cell)      → 3D 法向                                    │
│  - face_centroid(cell)    → 3D 重心                                    │
│  - face_area(cell)        → FaceAttr[5]                                │
│  - face_ftype(cell)       → PLANE / CYL / OTHER                        │
└───────────────────────────────────┬────────────────────────────────────┘
                                    ↓
┌────────────────────────────────────────────────────────────────────────┐
│  build_face_graph(part) → edges, fa_attrs                              │
│  ──────────────────────────────────────────                             │
│  代码：[edge_features.py:build_face_graph()](YHCADSmartCleaner/utils/through_step/featurefox_ncti/edge_features.py)│
│                                                                        │
│  对每对相邻面 (fa, fb)：                                                  │
│    - 计算 30 维边特征向量 e["features"]                                  │
│    - 记录 e["fa"], e["fb"], e["key"]                                    │
└───────────────────────────────────┬────────────────────────────────────┘
                                    ↓
═══════════════════【第一级：边分类器】═══════════════════════════════════════
                                    ↓
┌────────────────────────────────────────────────────────────────────────┐
│  XGBoost 边分类器                                                       │
│  ─────────────────                                                       │
│  代码：[predict.py:predict_through_slots()](YHCADSmartCleaner/utils/through_step/featurefox_ncti/predict.py)│
│                                                                        │
│  输入：30 维 × N_edges                                                  │
│  模型：[edge_clf.json](YHCADSmartCleaner/utils/through_step/featurefox_ncti/edge_clf.json)（200 树/深度 6）│
│  输出：每条边的 P(这条边在通槽内部)                                       │
│                                                                        │
│  后处理：                                                                │
│  1. 等温校准（3-fold CV） → 校准概率                                     │
│  2. 剪枝：P ≥ 0.35 留下                                                 │
│  3. 连通分量：留下的边按邻接聚团 → 候选实例                                 │
│  4. 初步过滤：n_faces ≥ 3 + 平面占比 ≥ 50%                              │
└───────────────────────────────────┬────────────────────────────────────┘
                                    ↓
═══════════════════【第二级：实例分类器】═══════════════════════════════════════
                                    ↓
┌────────────────────────────────────────────────────────────────────────┐
│  extract_instance_features(part, fa_attrs, conv_map, cell_ids, ...)     │
│  ────────────────────────────────────────────────────────────            │
│  代码：[instance_features.py:extract_instance_features()](YHCADSmartCleaner/utils/through_step/featurefox_ncti/instance_features.py)│
│                                                                        │
│  输入：每个候选实例的 cell_id 集合                                         │
│  输出：26 维聚合特征向量                                                  │
│                                                                        │
│  XGBoost 实例分类器                                                      │
│  模型：[inst_clf.json](YHCADSmartCleaner/utils/through_step/featurefox_ncti/inst_clf.json)（200 树/深度 4）│
│  输出：当前二分类 P(真通槽)                                              │
│  P < 0.80 → 拒绝（剔除 seg=22 等伪通槽）                                  │
└───────────────────────────────────┬────────────────────────────────────┘
                                    ↓
┌────────────────────────────────────────────────────────────────────────┐
│  输出：list[实例]                                                        │
│  ────────────────                                                       │
│  每个实例 = {                                                            │
│    "faces": [cell_id, ...],    ← 直接是 ai.FaceID 位置索引，零映射        │
│    "score": float,             ← 第一级平均概率                          │
│    "n_faces": int,             ← 实例大小                                │
│    "inst_prob": float,         ← 第二级置信度                            │
│  }                                                                      │
│                                                                        │
│  → GUI 高亮 / 标注 / 清理 / 下游训练                                    │
└────────────────────────────────────────────────────────────────────────┘
```

### 2.2 关键技术决策

| 决策 | 选择 | 理由 |
|---|---|---|
| **数据源** | NCTI 原生（不解析 STEP） | cell_id 零映射，避免曲面映射不可靠 |
| **符号约定** | concave=+1 / convex=-1 / smooth=0 | 与 STEP 版一致，便于对比 |
| **NCTI 导入** | 约定 A（doc.New + RunCommand） | 与 Geo-Rec 训练建图一致 |
| **校准** | 等温校准（3-fold CV） | FeatureFox 论文原方案 |
| **训练样本** | 组件同源（用第一级剪枝连通分量作训练样本） | 保证 train/serve 一致 |
| **特征工程** | 30+26 维手工特征 | 见 [§5](#5-特征来源拆解) |

#### 3.1.1 NCTI 数据来源（**字段 → NCTI 函数 → 行号**）

> **核心结论**：30 维特征**全部从 NCTI `AiModel` 数据**直读，**无 STEP 文本反推**。
> 数据后端封装：[ncti_backend.py](YHCADSmartCleaner/utils/through_step/featurefox_ncti/ncti_backend.py) `NctiPart` + `NctiFaceAttrs`。
> 建图入口：[edge_features.py:175-220](YHCADSmartCleaner/utils/through_step/featurefox_ncti/edge_features.py#L175-L220) `build_face_graph(part)`。

| 特征 | NCTI 字段 / 接口 | 后端函数（行号） | 说明 |
| --- | --- | --- | --- |
| **`dihedral_sign`** | `EdgeAttr[0/1/2]` 离散符号化 | `NctiPart._build_edge_tables`：[ncti_backend.py:120-124](YHCADSmartCleaner/utils/through_step/featurefox_ncti/ncti_backend.py#L120-L124) → `edge_dihedral[key]` | concave=+1 / convex=-1 / smooth=0（与 STEP 版对齐） |
| **`abs_dihedral`** | 由 `dihedral_sign` 派生 | 同上 | 把 ±1 映成 1.0 绝对值 |
| **`is_concave`** / **`is_convex`** / **`is_smooth`** | `EdgeAttr[0/1/2]` one-hot | `NctiPart.edge_convexity(key)`：[ncti_backend.py:65, 121](YHCADSmartCleaner/utils/through_step/featurefox_ncti/ncti_backend.py#L65) | 字符串 → one-hot |
| **`is_conv_unknown`** | 兜底 one-hot | 同上 | 凸凹性缺失时为 1 |
| **`edge_length`** | `EdgeAttr[3]` 累加 | `NctiPart._build_edge_tables`：[ncti_backend.py:104-108](YHCADSmartCleaner/utils/through_step/featurefox_ncti/ncti_backend.py#L104-L108) → `edge_length_map[key]` | 同一对面多条共享边累加 |
| **`edge_length_norm`** | 边长 ÷ `total_perimeter` | `NctiFaceAttrs.total_perimeter`：[ncti_backend.py:214-218](YHCADSmartCleaner/utils/through_step/featurefox_ncti/ncti_backend.py#L214-L218) | 总周长兜底 1.0 防除零 |
| **`edge_is_line`** | `EdgeAttr[9] == 1` | `NctiPart._build_edge_tables`：[ncti_backend.py:111-116](YHCADSmartCleaner/utils/through_step/featurefox_ncti/ncti_backend.py#L111-L116) | 直线 one-hot |
| **`edge_is_circle`** | `EdgeAttr[4] == 1` | 同上 | 圆弧 one-hot |
| **`edge_is_other`** | 上述皆否 | 同上 | 其他曲线 one-hot |
| **`face_a_area`** / **`face_b_area`** | `FaceAttr[5]` | `NctiPart.face_area(cell)`：[ncti_backend.py:151-156](YHCADSmartCleaner/utils/through_step/featurefox_ncti/ncti_backend.py#L151-L156) → `NctiFaceAttrs.area` 缓存 | 直接读 FaceAttr[5] |
| **`area_ratio`** / **`log_area_ratio`** | 上面两面积派生 | 在 `edge_features.py:50-65` 现场算 | min/max 与 log |
| **`face_a_perim`** / **`face_b_perim`** | 邻接边长度之和 | `NctiPart.face_perimeter(cell)`：[ncti_backend.py:167-173](YHCADSmartCleaner/utils/through_step/featurefox_ncti/ncti_backend.py#L167-L173) → `NctiFaceAttrs.perimeter` 缓存 | 遍历 adjacency 累加 `edge_length_map` |
| **`perim_ratio`** | 两周长派生 | `edge_features.py` 现场算 | min/max |
| **`centroid_dist`** | 两面 UV(0.5,0.5) 重心距离 | `NctiPart.face_centroid(cell)`：[ncti_backend.py:141-149](YHCADSmartCleaner/utils/through_step/featurefox_ncti/ncti_backend.py#L141-L149) → `GetFacePointFromUV(0.5,0.5)` | 3D 欧氏距离 |
| **`normal_angle_deg`** / **`normal_dot`** | 两面 UV(0.5,0.5) 法向 | `NctiPart.face_normal(cell)`：[ncti_backend.py:131-139](YHCADSmartCleaner/utils/through_step/featurefox_ncti/ncti_backend.py#L131-L139) → `GetNormalByUV(0.5,0.5)` | PLANE 恒定，CYL 给 UV 中心径向法向 |

### 4.1 26 维特征分组

代码：[instance_features.py:35-65](YHCADSmartCleaner/utils/through_step/featurefox_ncti/instance_features.py#L35-L65)

| 分组 | 数量 | 特征名 | 来源 |

| **面积统计** | 6 | area_total, area_min, area_max, area_mean, area_std, area_ratio_minmax, area_bottom_ratio | `FaceAttr[5]` numpy 聚合（`NctiPart.face_area`） |

| **合计** | **26** | | —— |

#### 4.1.1 NCTI 数据来源（**字段 → NCTI 函数 → 行号**）

> **核心结论**：26 维实例特征 = **对一组 cell_id 集合，调用 §3.1 同样的 `NctiPart` / `NctiFaceAttrs` 接口**做聚合（面积、周长、凸凹、ftype） + **加第一级 XGBoost 输出概率**。
> 实例特征计算入口：[instance_features.py:30-180](YHCADSmartCleaner/utils/through_step/featurefox_ncti/instance_features.py#L30-L180) `extract_instance_features(part, fa_attrs, conv_map, cell_ids, edge_proba_dict)`。
> `fa_attrs` 即 `NctiFaceAttrs(part)`，`conv_map` 即 `part.edge_convexity`。

| 特征 | NCTI 字段 / 接口 | 后端函数（行号） | 说明 |
| --- | --- | --- | --- |
| **`n_faces`** | 实例 cell_id 集合大小 | `len(cell_ids)` 现场算 | 直接数 |
| **`n_edges_internal`** | 邻接矩阵对角外非零数 | `part.adjacency` 内查（[ncti_backend.py:64, 88-90](YHCADSmartCleaner/utils/through_step/featurefox_ncti/ncti_backend.py#L64)） | 实例内部面相邻对 |
| **`faces_per_edge`** | 派生 | 现场算 | n_faces / n_edges_internal |
| **`n_plane`** / **`n_cyl`** / **`n_other`** | `FaceAttr[0/1]` | `NctiPart.face_ftype(cell)`：[ncti_backend.py:158-165](YHCADSmartCleaner/utils/through_step/featurefox_ncti/ncti_backend.py#L158-L165) | 三类面计数 |
| **`plane_ratio`** | 派生 | 现场算 | n_plane / n_faces |
| **`has_cyl_wall`** | 派生 | 现场算 | n_cyl ≥ 1 |
| **`area_total`** / **`area_min`** / **`area_max`** / **`area_mean`** / **`area_std`** | `FaceAttr[5]` | `NctiPart.face_area(cell)`：[ncti_backend.py:151-156](YHCADSmartCleaner/utils/through_step/featurefox_ncti/ncti_backend.py#L151-L156) → `NctiFaceAttrs.area` 缓存 | 5 个面面积的 numpy 聚合 |
| **`area_ratio_minmax`** | 派生 | 现场算 | min/max |
| **`area_bottom_ratio`** | 派生 | 现场算 | 最大面（≈底面）面积 / total |
| **`perim_total`** / **`perim_mean`** / **`perim_ratio_minmax`** | 邻接边长之和 | `NctiPart.face_perimeter(cell)`：[ncti_backend.py:167-173](YHCADSmartCleaner/utils/through_step/featurefox_ncti/ncti_backend.py#L167-L173) → `NctiFaceAttrs.perimeter` 缓存 | 遍历 adjacency 累加 `edge_length_map` |
| **`concave_edge_ratio`** / **`convex_edge_ratio`** / **`smooth_edge_ratio`** | `EdgeAttr[0/1/2]` 聚合 | `NctiPart.edge_convexity(key)`：[ncti_backend.py:65, 121](YHCADSmartCleaner/utils/through_step/featurefox_ncti/ncti_backend.py#L65) → `edge_convexity` | 实例内每条边的凸凹字符串计数 |
| **`n_perp_walls`** | 派生 | 现场算（法向 · 底面法向 ≈ 0） | 用 `NctiPart.face_normal(cell)` [ncti_backend.py:131-139](YHCADSmartCleaner/utils/through_step/featurefox_ncti/ncti_backend.py#L131-L139) |
| **`has_bottom_wall_split`** | 派生 | 现场算 | 是否有底-壁分裂 |
| **`bottom_perp_count_mean`** | 派生 | 现场算 | 底-垂直壁平均对数 |
| **`edge_prob_mean`** / **`edge_prob_min`** | **第一级 XGBoost 输出** | 推理时来自 `predict.py:65-90` / 训练时来自第一级 `predict_proba` → `calibrator.predict` | 第二级**复用第一级**的边概率作为强先验 |

> **关键点 1**：26 维 = 25 维 NCTI 几何聚合 + 1 维第一级概率。
> 几何聚合用的全部是 `NctiPart` / `NctiFaceAttrs` 同一套接口，**与第一级 30 维共用数据源**（避免重复读 NCTI 字段），保证 train/serve 分布一致。
>
> **关键点 2**：`n_perp_walls` / `has_bottom_wall_split` / `bottom_perp_count_mean` 是团队**自创**的"底-壁垂直对"信号——通过 `NctiPart.face_normal`（UV 中心法向）算夹角 ≈ 90° 来识别"垂直壁"。**没有专门的 NCTI 字段**，是几何推导。
>
> **关键点 3**：第一级概率（`edge_prob_mean` / `edge_prob_min`）是第二级最关键的"先验特征"——记忆里 featurefox §10 也强调过这是两级模型比单级 F1 高 4 个点的主要原因。

### 4.2 XGBoost 模型

| 参数 | 值 |
|---|---|
| `n_estimators` | 200 |
| `max_depth` | 4（比第一级浅，避免过拟合） |
| `learning_rate` | 0.1 |
| `subsample` | 0.8 |
| 校准 | isotonic |
| 拒绝阈值 | **0.80** |
| 输出 | 二分类 P(真通槽) |
| 模型文件 | [inst_clf.json](YHCADSmartCleaner/utils/through_step/featurefox_ncti/inst_clf.json) (370KB) + [inst_calibrator.pkl](YHCADSmartCleaner/utils/through_step/featurefox_ncti/inst_calibrator.pkl) |

### 4.3 为什么需要第二级？

第一级的"冤假错案"里，**72% 是 seg=22** 这种和通槽长得一模一样的"穿透型结构"。它们在**单条边**的几何上和通槽完全一样，第一级分不开。只有**整体看**才能区分。

## 5. 特征来源拆解

> ⚠️ **核心澄清**：30 维和 26 维特征**不是 FeatureFox 论文的精确复现**。

### 5.1 论文给的是什么

FeatureFox 论文 ([_paper_text.txt:258-260](YHCADSmartCleaner/utils/through_step/featurefox_ncti/_paper_text.txt#L258-L260)) 原话：

> "Edge attributes include the **dihedral angle, concavity, area and perimeter ratios, normalized length and distance between face centroids and the edge class** among others."

**只给了大类名**，并且论文 ([_paper_text.txt:103-104](YHCADSmartCleaner/utils/through_step/featurefox_ncti/_paper_text.txt#L103-L104)) 明确：

> "Due to internal company policy and confidentiality constraints, we **cannot publicly release the code and data** for this work."

### 5.2 30 维边特征的实际来源

| 来源 | 贡献特征 | 数量 |
|---|---|---|
| **FeatureFox 论文** (Fuchs et al. 2026, Siemens) | dihedral_sign / abs_dihedral / is_concave / is_convex / is_smooth / area_ratio / log_area_ratio / perim_ratio / edge_length_norm / centroid_dist / edge_is_circle | ~12 维 |
| **AAGNet 论文** (Wu et al. 2024) | edge_is_line / edge_is_other / face_a_is_plane/cyl/other / face_b_is_plane/cyl/other | ~10 维 |
| **Joshi & Chang** (1988) | AAG 凸凹性概念（不是单独特征） | 概念性 |
| **团队自创** | both_plane / plane_cyl / both_cyl / normal_angle_deg / normal_dot / edge_length（绝对值） | ~5 维 |

### 5.3 26 维实例特征的实际来源

| 来源 | 贡献特征 | 数量 |
|---|---|---|
| **FeatureFox 论文** | n_faces / n_edges / log characteristic length | ~3 维 |
| **团队设计** | 面积分布 / 周长分布 / 凹凸占比 / 底壁结构 / 一级置信度 | ~23 维 |

### 5.4 对外汇报的话术

> "我们的特征设计**借鉴**FeatureFox 论文的两阶段框架和核心思路（凸凹性、面积比、归一化长度、面重心距），但**不是直接照抄**——因为论文本身不公开精确特征定义。具体 30 维边特征和 26 维实例特征是**我们结合 FeatureFox、AAGNet 和 1988 年 Joshi & Chang 经典文献，再加上领域经验综合设计**的。这种做法的好处：可以针对通槽这一类特征**做特化调整**（比如加入'底面-壁面垂直对数'这种领域信号）。"

## 8. 瓶颈诊断

> 找出"为什么不能再上一个台阶"的关键问题。

### 瓶颈 1：特征工程的表达力天花板 🟡

**现象**：dihedral_sign 占重要性 62%，剩下 28 维重要性分散。
**原因**：30 维是手工定义，没有非线性组合能力。
**机会**：借鉴 **BRepFormer 2025**（Transformer 自动学特征）或 **Hierarchical CADNet 2022**（层级 pooling）。

### 瓶颈 2：单类限制 🔴

**现象**：训练数据有 25 类标注，但模型只输出"通槽 vs 非"。
**影响**：其他 24 类特征（圆角/倒角/各类孔）识别后**全部丢弃**——**信息浪费**。
**机会**：FeatureFox 论文原始目标就是 panoptic，我们目前只做了"半截"。

### 瓶颈 3：真实件泛化 🔴

**现象**：训练全合成件（OCC 生成），真实工业件可能因 cell_id 错位而跳过。
**影响**：产品化时真实件识别率会下降。
**机会**：FeatureFox 论文用 270 件真实件微调即可解决。我们仓库 [Geo-Data-Management](d:/wyg/xuntuiyitihua/Geo-Data-Management) 有真实件基础。

### 瓶颈 4：评估指标不完整 🟡

**现象**：当前用 F1，但 F1 不能区分"切分错"和"分类错"。
**影响**：调试时不知道该改第一级还是第二级。
**机会**：FeatureFox 论文用 PQ（panoptic quality）。仓库里 [evaluate_pq.py](YHCADSmartCleaner/utils/through_step/featurefox_ncti/evaluate_pq.py) 已有雏形。

### 瓶颈 5：断开实例不支持 🟡

**现象**：一连通分量 = 一实例。多操作特征（如两个不连通圆筒组成的孔）识别不了。
**影响**：覆盖 ~5~10% 工业件。
**机会**：FeatureFox 论文 §V 自陈未解决，是开放问题。

### 瓶颈 6：推理性能 🟢

**现象**：XGBoost 加载慢（1~2 秒），推理 ~100ms。
**影响**：GUI 高亮时会有顿挫感。
**机会**：ONNX 导出 + 量化。

## 13. 风险与取舍

### 13.1 关键风险

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| 多类扩展时某 seg 类别样本不足 | 中 | 中 | 加 class_weight / focal loss |
| 真实件微调后合成件精度下降 | 中 | 中 | 保留合成件 base + 真实件 adapter |
| 拓扑辅助任务与主任务冲突 | 低 | 低 | 加 loss 权重平衡 |
| GNN 替换 XGBoost 后样本效率下降 | 高 | 中 | **不替换，只在大数据场景并行** |
| OCC 版本升级导致 FaceAttr 布局变化 | 中 | 高 | 面数断言 + 字段版本检查 |

### 13.2 关键取舍

| 维度 | 选 X | 选 Y | 建议 |
|---|---|---|---|
| **XGBoost vs GNN** | 样本效率高、推理快、可解释 | 表达力强、大数据上限高 | **先用 XGBoost + 优化 4（混合特征）**；数据 >10 万件再考虑 GNN |
| **手工 vs 自动特征** | 可解释、调试简单 | 表达力强 | **保留 30 维 backbone + 加 12 维可学习 embedding**（优化 4） |
| **二分类 vs 多类** | 训练数据足（seg=22 负样本丰富） | 复用模型到 5+ 特征 | **优先做多类**（优化 1），与论文对齐 |
| **合成 vs 真实件** | 合成件量大、标注便宜 | 真实件反映工业实际 | **合成 pretrain + 真实件 finetune**（优化 2） |
| **单类 vs 多类训练数据** | 6 万件标注已包含 25 类 | 需要重新校验 25 类标签完整性 | **先 audit 标签完整度，再启动多类训练** |

### 13.3 已知功能 gap

参考 [featurefox_ncti/CLAUDE.md "风险" 段](YHCADSmartCleaner/utils/through_step/featurefox_ncti/CLAUDE.md)：

1. **NCTI 运行时依赖**：训练 + 推理都要 NCTI SDK + yhcad_py312
2. **性能**：NCTI 导入 ~0.3s/件 vs STEP 正则 ~5ms/件；62495 件训练 ~5h+
3. **shell==ai.FaceID 假设**：OCC 合成数据成立；真实工业件 NCTI 可能合并共面致假设破裂
4. **多类扩展**：本路线通槽单类（seg=9）。多类 panoptic 列为后续
