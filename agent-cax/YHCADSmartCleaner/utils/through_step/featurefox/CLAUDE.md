> **一句话定位**：基于 FeatureFox 论文路线（XGBoost 边分类 + 图剪枝 + 实例分类）的**两级数据驱动通槽识别**，

## §0 执行摘要（一页讲清）

| 维度 | 规则式 v5（基线） | **FeatureFox 两级（当前最优）** |
|---|---|---|
| 方法 | 人工评分公式（几何特征加权） | 数据驱动：XGBoost 学习 + 图分割 |
| Precision | 45.25% | **91.66%**（阈值 0.80，精度优先）|
| Recall | 63.48% | 79.31% / 83.18%（阈值 0.50）|
| F1（面级） | 52.84% | **85.04% / 85.96%** |
| 提升 | — | **F1 +32pt** |

**三句话讲清做法**：
1. **痛点**：通槽的"真"（TP）和"假"（FP）在单个几何特征上高度重叠，手工评分线性不可分 → 规则式封顶 ~53%。
2. **破局**：借鉴 FeatureFox 论文，把"识别通槽"转成**边分类问题**——用 XGBoost 从 17800 个标注样本学习"每条边是否在通槽内部"，再用**连通分量**自动还原通槽实例，让模型而非人工去组合多维特征。
3. **补刀**：seg=22（其它穿透型特征）在**边级别**几何上与通槽几乎同构，第一级分不开——于是加**第二级实例分类器**，用"整实例聚合特征"做语义判定，把同类误检剔除。

## §1 背景与痛点：规则式为什么封顶

**业务背景**：通槽（through step，双侧贯通的台阶槽）是机加特征识别 (AFR) 中的难点。识别准了，下游才能正确做工艺规划（刀具路径、特征清理）。

**规则式路线（v4→v5）的演进与天花板**：
- v4 引入"边凸凹性"（从 STEP 几何反推），F1 从 48.84% → 54.42%；
- v5 改进评分维度（反平行度 + 质心对称性），全量 17800 文件 F1 = **52.84%**；
- 再加 NCTI 版的 mixed_trio 搜索路径实测**不适用 STEP 版**（无边凸凹性数据，圆柱壁匹配太宽松，只增 FP）。

**根本瓶颈**：规则式本质是"若干几何特征 × 人工权重"的**线性评分**。但通槽的 TP 和 FP 在每个单一维度（垂直度、重心位置、面积比、开放度……）上**评分区间高度重叠**（如 TP 73–100 分、FP 也 73–100 分）——**线性不可分**。继续调权重/加阈值只会**Precision 与 Recall 此消彼长**，无法同时提升。这正是规则方法的固有极限。

**结论**：要突破，必须让模型去学习**多维特征的非线性组合**——即数据驱动。这是采用 FeatureFox 路线的根本动因。

## §2 论文依据：FeatureFox 是什么

**出处**：FeatureFox — *Sample-Efficient Panoptic Graph Segmentation for Machining Feature Recognition in B-Rep 3D-CAD Models*（**Fuchs, Kacan, Haag, Lohse**, arXiv:2604.26770v1, **2026-04-29**）。

- 作者单位：Technische Universität Berlin / Siemens AG, München / Friedrich-Alexander-Universität Erlangen-Nürnberg。
- arXiv 全文：<https://arxiv.org/html/2604.26770v1>
- **本地 PDF 已存**：`FeatureFox_2604.26770v1.pdf`（本目录，6 页 / 809 KB），可离线查阅。

> 注：代码注释里仍沿用旧的 "Fuchs et al., 2025" 写法——准确年份应为 **2026**（论文 2026-04-29 提交）。后续清理代码注释时一并更正即可，不影响功能。

### 2.1 论文要解决什么问题

把 B-Rep 3D-CAD 模型上的**加工特征识别 (AFR)** 定义为一个 **Panoptic Segmentation（全景分割）** 任务——即同时输出：
- **每个特征实例包含哪些面**（实例分割 / 定位）；
- **每个实例是什么特征类别**（语义分类）。

并用一个统一指标 **Panoptic Quality (PQ)** 联合评分"是哪种特征"和"具体是哪些面"。

### 2.2 论文的核心方法（与我们直接相关的三段式管线）

论文提出一个**层次化、基于树模型、可解释**的管线（Figure 3）：

```
(1) 丰富化边属性  ：把相邻面的信息传播到 B-Rep 边上，拼接成增强特征向量
(2) 校准的边边界分类器：XGBoost 预测"两边是否属同一特征实例" → 概率阈值化
    → 剪枝面邻接图的连通分量 = 特征实例（实例定位）
(3) 每实例语义分类器  ：对每个连通分量聚合子图属性 → XGBoost 预测特征类别
```

**关键细节（论文原文照录，与我们实现一一对应）**：

1. **图表示**：面邻接图 G=(V,E)，每个面一个节点，共享 B-Rep 边的两面之间连一条边（2-manifold 假设下每条边恰属两面）。这是 UV-Net/AAGNet 的 gAAG 表示。

2. **丰富化边属性（enriched edge attributes）**：把边自身属性与两个相邻面的属性组合。论文明确列举的边属性包括——
   > *"the dihedral angle, concavity, area and perimeter ratios, normalized length and distance between face centroids and the edge class among others."*
   即：**二面角、凹凸性、面积比、周长比、归一化长度、面重心间距、边类型**。

3. **标注范式（labelling paradigm）—— 二分类边分类**：对连接相邻面 i、j 的每条图边 k：
   > y_k = [ℓ(i) == ℓ(j)] ∈ {0,1}，**当且仅当两边属于同一加工特征实例时为正**。

4. **校准的二分类边分类器**：
   > *"a calibrated binary XGBoost classifier with 200 trees (maximum depth 6, learning rate 0.1)"*
   - 超参：**200 棵树、最大深度 6、学习率 0.1**（固定先验，不做超参搜索）。
   - 因为实例定位依赖**概率阈值化**，必须用**校准良好的概率** → **isotonic calibration（等渗校准），3 折交叉验证**。

5. **连通分量恢复实例**：给定面邻接图 G 与预测边标签 ŷ_k，只保留 ŷ_k=1 的边得到剪枝图 Ĝ，**每个特征实例 = Ĝ 的一个连通分量**。

6. **每实例语义分类器**：与 AAGNet 的"逐面分类"不同，FeatureFox 对**每个完整实例**分类。对每个 GT 实例（连通节点集 C）聚合出一个实例属性向量 z_C（面/边数、log 特征长度、面/边类型直方图、曲率分布、图拓扑特征如谱连通性、边界边环数等），训练**语义 XGBoost（400 棵树、深度 6）**。

### 2.3 论文亮点（为什么这条路线适合我们）

| 论文主张 | 数据 | 对我们的意义 |
|---|---|---|
| **样本高效** | ~250 训练零件即 PQ>0.9（深度基线 AAGNet 需 ~5000） | 我们有 17800 标注零件，远超所需，**数据足够** |
| **计算高效** | 全量训练 8 秒（AAGNet 38 分钟） | 无需 GPU，CPU 即可，**部署成本低** |
| **可解释** | 树模型 + 特征重要性透明 | 凸凹性占重要性 62%，**可向领导讲清模型在学什么** |
| **与 SOTA 相当** | 全量上 PQ 略低于 AAGNet（96.87 vs 97.44），但特征级定位略优 | 单类任务下足够，且不依赖 GNN 基础设施 |
| **轻量、可落地** | 树模型，推理 O(\|V\|+\|E\|) | 可直接集成进桌面端 GUI |

> **数据集规模与工业验证（论文原文佐证）**：
>
> - 论文在 **MFInstSeg** 上训练（62,477 个 STEP 成功转换 62,178 个，全量训练集 **43,524 件**）。
> - 仅用 **270 个手标真实 NX 零件**训练，在**未参与训练的 NIST 工业测试件**上定性泛化——孔/槽/口袋均识别正确（论文 Figure 5）。
> - → 佐证该路线**真实工业 CAD 可用、非纯合成数据**；我们的 **17,800 标注件远超其 250 件的低数据门槛**。
> - 面级实例分割 F1（论文 Table I）：FeatureFox **99.45%** vs AAGNet 98.84% / MFTReNet 98.90%——实例定位能力与深度模型相当甚至略优。

## §3 我们的技术路线（两级架构详解）

我们**复用论文的三段式骨架**，针对**单类通槽识别**做了适配，并针对 STEP 数据的同类误检问题加了**第二级实例分类器**。

### 3.1 整体流程

```
STEP 文件
  ↓ StepParser 解析（不依赖 NCTI，纯 STEP 拓扑/几何）
第一级 ─ 边分类器（管召回：把高概率边连成候选实例）
  │  ① 构建带属性面邻接图 AAG：每条共享边算 30 维特征
  │  ② XGBoost 预测 P(这条边在通槽内部)
  │  ③ 等渗校准概率
  │  ④ 剪枝：保留概率 ≥ 0.35 的边
  │  ⑤ 连通分量 = 候选通槽实例
  │  ⑥ 后处理：面数 ≥ 3 且平面占比 ≥ 50%
  ↓
第二级 ─ 实例分类器（管精度：剔除 seg=22 同类误检）
  │  每个候选实例 → 提取 26 维聚合几何特征（含第一级边概率）
  │  → XGBoost 预测 P(真通槽)
  │  → P < 0.80 → 拒绝
  ↓
输出：通槽实例列表（faces / score / inst_prob）
```

### 3.2 第一级：边分类器（对应论文的"校准边边界分类器"）

**为什么把"识别通槽"转成"边分类"？** 通槽 = 底面 + 两壁。底面-壁面、壁面-壁面之间的**共享边**就是"通槽内部的边"。如果能判定哪些边属于"通槽内部"，这些边自然把通槽的面连成一个连通块——**边分类等价于实例分割**。这是论文的核心洞见，我们直接采用。

- **边特征（30 维，见 §10）**：与论文列举的边属性**一一对应**——凸凹性（二面角符号值 + one-hot）、边长度/类型、面面积/周长比、面重心距、法向量夹角、面类型组合。其中**凸凹性占特征重要性 62%**，是模型最依赖的信号。
- **标签**（单类简化）：
  - **y=1（正样本）**：共享边两端面同属一个通槽实例（seg=9 且 `inst[i][j]=1`）；
  - **y=0（负样本）**：所有其他边。
  - 论文是"两边同属任一特征实例"，我们简化为"两边同属**通槽**实例"（单类任务）。
- **训练**：17800 文件，正样本仅 5.2%（类别极不平衡，用 `scale_pos_weight`）。
- **超参（照搬论文）**：200 棵树 / 深度 6 / 学习率 0.1；**等渗校准**。
- **剪枝 + 连通分量**：对校准概率施加阈值 0.35（扫描实测最优），保留高概率边，连通分量即候选实例。

### 3.3 第二级：实例分类器（我们的关键适配）

**为什么需要第二级？** 这是规则式和数据驱动**单级**都会遇到的真问题：

> 第一级分不开的，是 **seg=22（其它穿透型特征）**——它们在**边级别**几何上与通槽**几乎同构**（同样是底+壁、同样凹边为主、同样垂直结构）。实测 **72% 的 FP 面来自这种整组 seg≠9 的误检实例**。

**解法**：换一个**尺度**去看。seg=22 在"边级别"和通槽同构，但在**整实例聚合**层面有差异（面积/周长分布、凹边占比的细微差异、底-壁结构、以及第一级对这个实例的整体置信度）。于是加第二级——这正是论文"每实例语义分类器（聚合子图属性）"的思想：

- **实例特征（26 维，见 §10）**：规模（面/边数）+ 面类型构成 + 面积/周长分布 + 凹凸边占比 + 底-壁垂直结构 + **第一级对该实例的边概率（置信度）**。
- **标签**：y=1 = 整组 seg=9（真通槽）；y=0 = 整组 seg≠9 且 ≠0（其它特征，含 seg=22）。
- **超参**：200 棵树 / 深度 4 / 学习率 0.1 / subsample 0.8；等渗校准；阈值 0.80（精度优先，见 §11）。

**最关键的工程经验（踩过的大坑）——训练/推理必须同源**：
第二级的训练样本必须是**推理时真正会看到的对象**，即【第一级边剪枝后的连通分量】，**而不是**标注 inst 矩阵里的真实实例分组。否则分布错位：seg=22 的 9 面真实实例被当负例训练，但推理时只有它的 3 面子分量到达分类器（3 面槽形训练时几乎只见过正例）→ 误判为通槽。这条经验花了三次迭代才定位（演进见 §6.1）。同理，实例特征必须传入**第一级边概率**，与推理一致。

### 3.4 模型文件的本质：200 棵决策树

`edge_clf.json` / `inst_clf.json` 不是黑盒权重矩阵，而是 **200 棵决策树的集合**，序列化成纯文本 JSON。两个分类器本质相同，只是树大小不同：

| 模型 | 大小 | 结构 |
|---|---|---|
| `edge_clf.json`（第一级） | 1.1 MB | 200 棵树 × 38 叶子 |
| `inst_clf.json`（第二级） | 367 KB | 200 棵树 × 15 叶子 |
| `calibrator.pkl`（校准器） | 2 KB | 概率换算表（等渗回归） |

**一棵决策树 = 一串 if-else**（`edge_clf` 第 1 棵树的真实片段）：

```text
0:[f0 < 7.68e-12] yes=1,no=2   # f0=凸凹性（树的第一判断就看它 → 印证重要性 62%）
 1:[f20 < 1] yes=3,no=4        # f20=法向点积
   3:leaf=-0.199               # 走到这，贡献 -0.199
   4:[f18 < 1.577] ...         # f18=重心距
```

**预测**：一条边进来，200 棵树各走一遍拿到叶子值，**累加 → logit → sigmoid → 概率**。每棵树修正前面树的残差（梯度提升），接力越来越准。前文 F8–F9 得到 0.92，就是这 200 个叶子值加出来的。

**为什么小、为什么快**：模型里只有"特征 + 阈值"和"叶子一个数"，`edge_clf` 全部 ≈ 7600 个叶子值。对比 AAGNet 的 **0.41M 参数权重矩阵**（几十 MB、需 GPU 矩阵乘法），决策树只是 200 次查表 if-else → CPU 秒级推理、文件 < 1.5 MB。代价是特征靠人设计、天花板受特征限制（见 §8）。

## §4 与论文的对应关系（哪些照搬 / 哪些适配 / 哪些是我们的创新）

| 环节 | FeatureFox 论文 | 我们的实现 | 关系 |
|---|---|---|---|
| 问题定义 | 通用多类 panoptic AFR | **单类**通槽识别 | **简化**（任务只关心通槽） |
| 图表示 | gAAG（UV-grid 张量 + 边采样张量） | 面邻接图 + 解析几何属性（法向量/面积/重心/周长） | **适配**（STEP 文本解析直接算，免 UV 采样） |
| 丰富化边属性 | dihedral/concavity/area·perim ratio/norm length/centroid dist/edge class | **30 维边特征**，逐项对应 | **照搬**（一一对应） |
| 边标签 | y=[ℓ(i)==ℓ(j)] 两边同属任一实例 | y=[两边同属**通槽**实例] | **简化为单类** |
| 边分类器 | XGBoost 200/depth6/lr0.1 + isotonic | **完全相同超参** | **照搬** |
| 实例恢复 | 剪枝面邻接图的连通分量 | 相同 + 后处理（面数≥3、平面占比≥50%） | **照搬 + 加约束** |
| 每实例分类 | 多类语义分类（聚合子图属性，XGBoost 400/depth6） | **二分类**（真通槽 vs seg=22 同类，XGBoost 200/depth4） | **适配**（专攻同类误检） |
| 训练同源性 | 论文用 GT 实例做语义分类 | **组件同源训练**（用推理时的边剪枝连通分量） | **我们的工程创新** |
| 评估指标 | Panoptic Quality (PQ) | 面级 Precision/Recall/F1（与既有基线可比） | **适配**（沿用项目既有评估口径） |

**一句话总结**：骨架（边分类 → 校准 → 连通分量 → 实例分类）**完整复刻论文**；适配点在"单类化"和"实例分类器专攻 seg=22 同类误检"；最大工程创新是"训练/推理组件同源"这条踩坑得来的经验。

## §5 实验结果与性能

### 5.1 与规则式基线对比（面级，holdout 500，训练集外 offset=14000）

| 实例阈值 | Precision | Recall | F1 | FP | FN |
|---|---|---|---|---|---|
| 0.50（F1 最优） | 88.94% | 83.18% | **85.96%** | 195 | 317 |
| **0.80（默认，精度优先）** | **91.66%** | 79.31% | **85.04%** | 136 | 390 |
| 0.95（最高精度） | 94.40% | 72.41% | 81.96% | 81 | 520 |

- **单级**（仅第一级）：P=79.59% R=85.84% F1=82.59%（基线对比）。
- **第二级实例分类器 test 集**（全量训练，组件同源）：**P=97.49% R=97.55% F1=97.52%**。
- **Top 实例特征重要性**：`edge_prob_mean`(45.0)、`n_faces`(41.4)、`n_edges_internal`(27.7)、`bottom_perp_count_mean`(15.0)、`edge_prob_min`(11.7)。
- **全量训练耗时**：边分类器 ~4.5min；实例分类器（组件同源，含每文件边推理）~18min。

### 5.2 可解释的验证案例（`_344`）

阈值 0.80 下：正确检出 2 个通槽 {6,7,18}/{14,15,23}（P=0.997 保留），seg=22 误检组 {25,26,28}（P=0.771 < 0.80 被拒）→ **TP=6 / FP=0 / FN=0，精确匹配标注答案**。这直观证明第二级"剔同类误检"的有效性。

### 5.3 项目内横向对比

| 方案 | Precision | Recall | F1 | 评估 |
|---|---|---|---|---|
| NCTI v2 规则式 | 30.10% | 34.83% | 32.29% | 50 文件 |
| STEP v5 规则式 | 45.25% | 63.48% | 52.84% | 全量 17800 |
| **FeatureFox 两级（0.80）** | **91.66%** | 79.31% | **85.04%** | holdout 500（训练外）|

**两级 vs 单级**：Precision +6.1pt、FP −38%、F1 +0.8pt（第二级实例分类器的贡献）。

## §6 演进历程与工程经验

### 6.1 第二级实例分类器的三级修复（踩坑史，汇报时可讲"如何定位真问题"）

1. **初版**（inst 矩阵真实分组训练，未传 edge_probs）：test F1=91.2%，但 `_344` 的 seg=22 误检 P=0.912 → **FP 未解决**。

3. **组件同源训练**（改用边剪枝连通分量作为训练样本，命中真根因）：test F1=97.5%，误检 P=0.771，阈值 0.80 拒掉 → **FP 解决**。

> 教训：test 指标高 ≠ 真问题解决。**train/serve 分布一致性**比模型本身更关键——这是部署机器学习最常被忽视、也最致命的一环。

### 6.2 STEP face → NCTI cell_id 映射（落地的最后一公里）

桥接层 [on_find_through_step_featurefox.py](YHCADSmartCleaner/function/on_find_through_step_featurefox.py) 已切换为**几何法 + ai.FaceID 位置索引**（2026-06-16，与标注管线 `annotate_through_step.py:build_step_to_ncti_pos_map` 完全一致）：

- **cell_id = `ai.FaceID` 位置索引**（0,1,2,…），与 Geo-Rec 训练标签空间严格对齐；
- **映射方法**：几何最近邻（双向 + 自适应容差 diag×0.15）—— NCTI `GetFaceMidPoint`（面中点）↔ STEP 面重心，互为最近且在容差内才匹配；
- 保证**训练标签 cell_id 空间与 GUI 高亮 cell_id 完全一致**，无论 NCTI 是否合并共面/删退化面。

## §7 为什么这条路能赢（方法论小结，汇报核心论点）

1. **把线性不可分的问题，换成可学习的非线性问题**——这是规则式 → 数据驱动的本质跃迁，F1 从 53% 到 85% 的来源。
2. **用"边分类"巧妙降维**——不直接预测"哪些面是通槽"（面级组合爆炸），而是预测"哪些边是通槽内部边"，再靠连通分量免费得到实例。优雅且高效。
3. **两级各司其职**——第一级管召回（边级几何足够把通槽面连起来），第二级管精度（实例级语义剔同类误检）。单级做不到的事，两级分工做到。
4. **论文背书 + 工程适配**——核心管线有学术依据（FeatureFox），单类化和"组件同源训练"是我们的落地创新，可解释、可复现、低算力。
5. **数据红利**——17800 标注零件，远超论文所示 250 件的起跑线，模型训练充分。

## §8.5 已知盲区：罕见"星形通槽"被第二级系统性误杀（2026-06-17 定位）

**症状**：`20221121_154647_101.step` 检测出 0 个通槽，但实际有（cell `{0,1,4}`）。这类漏检 holdout 上占含通槽文件的 ~15%（76/500 被第二级杀，其中 20 个第一级完全正确）。

**根因链（逐层定位，已用反事实+重训实验全部验证）**：

1. **第一级零失误**——通槽内部 2 条边都识别到（concave+90°垂直+两平面+直线，教科书特征），剪枝后连通分量 `{0,1,4}` **精确匹配真值**。第一级 raw_prob=0.946（高度自信）。
2. **等渗校准压低信号**——raw 0.946 因 area_ratio=0.316 偏小（正例均值 0.586），落在"raw 高但真实率 59%"区间，被校准成 0.595。校准本身没错，但把第一级的自信度区分度抹平了。
3. **真正主因 = `n_edges_internal=2`**：目标文件是**"两壁不相邻"的星形 3 面通槽**（底面连两壁、壁间无共享边）。而 3 面通槽（占 84.9% 最主流形态）中 **97.6% 是两壁相邻的（n_edges=3），仅 2.4% 是星形（n_edges=2）**。`n_edges_internal` 是第二级 top 特征（gain 12~25），训练数据里星形正例太少又被 seg=22 碎片负例混淆 → 模型学到"n_edges=2 → 多半非通槽"。
4. 第二级 inst_P=0.164 < 0.80 → 冤杀。同类星形通槽 inst_P 两极分化（0.164~0.992），印证模型在此形态上未学好。第二级 0.80 阈值整体误杀率 4.1%（67/1645），星形通槽占大头。

**已验证并证伪的快速修复**（均不能既救回此文件又不伤整体）：

| 方向 | 救回目标 | 整体 F1 | 失败原因 |
|---|---|---|---|
| 二级阈值 0.80→0.50 | ✗(0.164<0.50) | 85.27（+2.7pt） | 目标太低救不回；但此改动**整体有益**，推荐部署 |
| 几何豁免（严/宽/窄签名） | 部分 | 80~82 | seg=22 同类几何同构，FP 34→246~410 暴涨 |
| 去 edge_prob 重训（noep） | ✗(0.200) | 80.51 | edge_prob 是有用正信号，去掉整体更差 |
| raw edge_prob 重训 | ✗ | 83.95 | cal→raw 未触及真因(n_edges) |

**治本方向（未实施，需投入）**：对**星形通槽**（n_edges_internal=2，2.4%）过采样/类别加权，全量重训第二级（~90min）。预计能把 4.1% 误杀率显著降低。

**立即可部署的免费改进**：`INST_THRESHOLD` 0.80→0.50（`predict.py` 一行），整体 F1 +2.7pt，精度仍 95.35%。**救不回此文件**，但整体更优。

**诊断工具**（保留在模块内，可复用于排查其它漏检文件）：
- `_debug_one.py <step>` — 单文件两级管线逐层 dump（边概率/连通分量/实例特征/inst_P），秒级定位漏检发生在哪一级。
- `_stat_holdout.py [n] [offset]` — holdout stage 分桶（OK/L1_MISS/L1_PART/L2_KILL/L2_KILL_FULL）。

## §10 特征清单

「维」= 表格的一列、一个数字特征。第一级判断对象是**一条边**（30 维），第二级判断对象是**一个候选实例 / 一组面**（26 维）。

### 边特征（30 维，顺序见 `edge_features.FEATURE_NAMES`）—— 描述「一条边」

| 组 | 维数 | 特征 | 这组在问什么 |
|---|---|---|---|
| **凸凹性** | 6 | `dihedral_sign`, `abs_dihedral`, `is_concave/convex/smooth/unknown` | 这条边凹还是凸？弯多少？⭐占重要性 62% |
| 边几何 | 5 | `edge_length`, `edge_length_norm`, `is_line/circle/other` | 边多长？直线还是弧？ |
| 面面积 | 4 | `face_a/b_area`, `area_ratio`, `log_area_ratio` | 两端面各多大？比例？ |
| 面周长 | 3 | `face_a/b_perim`, `perim_ratio` | 两端面周长？ |
| 面间关系 | 3 | `centroid_dist`, `normal_angle_deg`, `normal_dot`(signed) | 两面法向夹角？重心多远？ |
| 面类型 | 6 | `face_a/b_is_plane/cyl/other` | 两端面各是什么曲面？ |
| 组合项 | 3 | `both_plane`, `plane_cyl`, `both_cyl` | 两面类型怎么搭配？ |

合计 6+5+4+3+3+6+3 = **30**。

### 实例特征（26 维，见 `instance_features.INSTANCE_FEATURE_NAMES`）—— 描述「一组面」

| 组 | 维数 | 特征 | 这组在问什么 |
|---|---|---|---|
| 规模 | 3 | `n_faces`, `n_edges_internal`, `faces_per_edge` | 这组几个面、几条内部边？ |
| 面类型构成 | 5 | `n_plane/cyl/other`, `plane_ratio`, `has_cyl_wall` | 平面/圆柱占比？ |
| 面积分布 | 7 | `area_total/min/max/mean/std`, `area_ratio_minmax`, `area_bottom_ratio` | 面积分布（底/壁面有特定比例） |
| 周长 | 3 | `perim_total/mean/ratio_minmax` | 周长分布 |
| 凹凸边占比 | 3 | `concave/convex/smooth_edge_ratio` | 内部边凹的占多少（通槽以凹为主） |
| 底壁结构 | 3 | `n_perp_walls`, `has_bottom_wall_split`, `bottom_perp_count_mean` | 有没有「1 底 + 2 垂直壁」U 型结构？ |
| 第一级置信度 | 2 | `edge_prob_mean`, `edge_prob_min` | 第一级对这组边有多确信？⭐ |

合计 3+5+7+3+3+3+2 = **26**。

### 两组特征的尺度对比（为什么需要两级）

| | 第一级 30 维 | 第二级 26 维 |
|---|---|---|
| 看的对象 | **一条边**（微观） | **一整组面**（宏观） |
| 特征性质 | 边的局部细节（凸凹、长度、两端面关系） | 一组面的统计分布（面积分布、凹边占比、底壁结构） |
| 解决什么 | 把通槽的面**连起来**（召回） | 把长得像的 **seg=22 误检剔掉**（精度） |
| 最关键特征 | 凸凹性 `dihedral_sign` | 第一级置信度 `edge_prob_mean` + 底壁结构 |

> seg=22 误检在**边级别**和通槽几乎同构（同样凹边、同样垂直），第一级 30 维分不开；但放到**整实例级别**，面积分布 / 凹边占比 / 底壁结构有细微差异 → 第二级 26 维分开。**两级是因为两个尺度各管一段。** 且第二级把 `edge_prob_mean`（第一级对这组边的平均置信度）作为一维传入，相当于「参考第一级的意见」。

## §12 标签语义

边分类器是**二分类**：
- **y=1（正样本）**：共享边两端的面同属一个通槽实例（两 cell_id 都在 seg=9 集合，且 `inst[i][j]=1`）
- **y=0（负样本）**：所有其他边

预测时连通分量自然恢复通槽（底面+两壁通过高概率边相连）。这是面向单类（通槽）的简化，FeatureFox 原文用通用实例分割+语义分类两阶段。

## §16 关键实现细节 / 易踩坑

1. **边长度 CIRCLE 计算用弦长反推小弧**：StepParser 不存 TRIMMED_CURVE 范围，只能取小弧 `r×2asin(chord/2r)`；闭合整圆（圆柱接缝边，两顶点重合）返回 `2πr`。

2. **预测必须传校准后的概率给剪枝**：`booster.predict()` → `calibrator.transform()`，不能直接用原始概率（0.5 阈值在原始概率下偏差大）。

3. **训练/评估要避免数据泄漏**：用 `offset` 参数让评估文件落在训练文件之外。`train.py` 内部按文件名分 train/calib/test（不是按边），保证同文件的边不会跨集合。

4. **类别不平衡**：正样本仅 5.2%，用 `scale_pos_weight = neg/pos`。XGBoost 默认不处理。

5. **DMatrix 接口**：predict 时用 `xgb.DMatrix(X)` + `booster.predict(dmat)`（不是 sklearn API），因为模型用 `booster.save_model` 保存为 Booster。

6. **实例分类器训练/推理必须同源**（最重要）：第二级训练样本必须是【边剪枝后的连通分量】（与推理一致），不能用 inst 矩阵的真实实例分组。否则分布不一致——seg=22 的 9 面真实实例训练为负，但推理时只有它的 3 面子分量到达分类器（3 面槽形训练时几乎只见正例）→ 误判为通槽。同理实例特征必须传 `edge_probs`（第一级边概率），与推理一致。

7. **`train()` 不要用 `TextIOWrapper` 重包装 stdout**：配合 `-u` 时会引入块缓冲，全量训练的实时进度被吞（曾因此误判"挂死"而误杀）。用 `PYTHONIOENCODING=utf-8` + `print(..., flush=True)`。
