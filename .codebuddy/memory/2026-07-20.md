# 2026-07-20

## 训练仪表盘进度条改为日志内文本渲染（train_dashboard.py）
- 用户反馈：不要单独的 `wx.Gauge` 控件（曲线与日志之间多占一行），应把进度条**直接渲染在日志里**（文本进度条，形如 `训练进度 [████░░] 60% (epoch 12/200)`）。
- 改动：删除 `wx.Gauge` / `progress_row` / `progress_label` 及 `_show_progress_row`；新增 `_render_progress_bar()` 在日志末尾追加一行文本进度条（█ 填充 + ░ 空位，宽 24）。
- 进度状态用 `self._progress_active` / `self._progress_fraction` / `self._progress_label` 维护：`set_work_dir` 激活，`finish_job` 关闭，`set_progress(fraction)` 存比例，`_on_log_timer` 在 graph 模式用 `(frac+0.09)%1.0` 循环脉冲。
- `_refresh_log` 在拼装日志时若 `_progress_active` 则追加进度行，随日志一起滚动刷新。
- 优势：用户看日志即知进度，少占一行空间；无新增 lint 错误。

## 进度条升级为「阶梯式逐行进度条」（用户选形态 3）
- 用户在前次提供了三种金字塔形态（填充式/生长式/阶梯式），最终选**形态 3：阶梯式逐行进度条**。
- `_render_progress_bar()` 改为 `_render_progress_lines()`，返回**多行列表**追加到日志末尾。
- 训练模式：以约 10% 为一级（`step = max(1, total//10)`），逐级列出已完成台阶 `epoch X/total [bar] pct%`，末尾追加当前 epoch 实时行（标 `◀当前`）；随训练推进逐行增长，右缘呈阶梯/三角轮廓，最多约 10 行不撑日志。
- graph 模式：无 epoch 概念，退化为单行脉冲进度条（`(frac+0.09)%1.0`）。
- `_refresh_log` 调用处改为 `tail_lines + self._render_progress_lines()`。无 lint 错误。

## 生成graph 也改为阶梯式逐行进度条
- 用户要求：graph 阶段也用阶梯式（同训练）。
- graph 分支改为：total 视作 10 级，按 `self._progress_fraction` 渲染 `生成graph进度 s/10 [bar] pct%` 阶梯，末行标 `◀进行中`。
- `_on_log_timer` 的 graph 脉冲由循环 `(frac+0.09)%1.0` 改为**单调爬升封顶 0.9**（`min(0.9, frac+0.01)`），避免阶梯长满又缩回显得像重来；停在接近满级表示"进行中、接近完成"。
- 无 lint 错误。

## 决策：不做"最佳 epoch 标记"（#3）
- 头脑风暴里我提议把"最佳 epoch（val_iou 最高）标进日志"，用户决定**不做**。
- 原因：模型权重本来就自动保存为 `best.pth`（即最佳验证指标的那个），用户直接拿 `best.pth` 用即可，无需在日志里再标最佳 epoch。
- 当前训练页改动止于：阶梯式进度条 + ETA/已用时长（均已入日志）。

## 澄清 + 阶梯日志加 ETA/已用时长
- 澄清：训练完成**本来就有 `wx.MessageBox` 弹窗 + 状态栏提示**（`on_train.py` 的 `_finish_train_job`，retcode==0 时弹"训练完成/ graph 生成完成"并附模型/ graph 路径）；ETA 也**已在状态栏**（`_build_train_status` 拼 `剩余≈6:40`）。我之前误判"无完成提示"是错误的。
- 用户决定：只把 ETA 加进**训练页日志阶梯**（状态栏已有，但用户看的是仪表盘日志，不顺手）。
- 实现（`train_dashboard.py`）：新增 `import time`、`self._start_time`（`set_work_dir` 时记 `time.time()`）、模块函数 `_format_duration(seconds)`。
  - 训练模式：阶梯末行追加 `⏱ 已用 3分25秒 · 约 1.0s/epoch · 剩余≈6分40秒`（cur_epoch>0 才显示）。
  - graph 模式：末行追加 `⏱ 已用 X · 进行中（无明确进度）`。
- 无 lint 错误。
