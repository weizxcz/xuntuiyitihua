# `featurefox_ncti` 模块技术路线

> **受众**：非技术读者、业务方
> **目的**：用尽量通俗的语言，把这条"AI 识别 CAD 通槽"路线的整体思路讲清楚
> **代码位置**：`YHCADSmartCleaner/utils/through_step/featurefox_ncti/`
> **作者备注**：所有数据/特征名都对应实际代码（`edge_features.py` / `instance_features.py` / `ncti_backend.py` / `predict.py`），可直接对照。
> ⚠️ **必读 1**：关于 "30 维/26 维特征是不是来自 FeatureFox 论文"——**不是精确复现**，是混合借鉴。详见 [§5.4 特征来源拆解](#54-特征来源拆解混合借鉴非单一论文)。
> ⚠️ **必读 2**：关于 "24 类" 概念——训练集标注 seg=0..24（共 25 类，其中 seg=9=通槽），但**第二级分类器当前是二分类**（真通槽 vs 非通槽），不是 24 分类。详见 [§6.3](#63-关于24-类的说明)。

## 一、TL;DR（一句话版本）

> **这条路线做的事**：用一个两级的"AI 看图师傅"模型，**自动识别 CAD 零件里的"通槽"**。
> **第一级**用 30 个数字描述"每条边长啥样"，判断这条边是不是通槽的内部边。
> **第二级**用 26 个数字描述"每个候选区域整体长啥样"，判断这个区域是不是真的通槽（剔除长相相似的伪通槽）。
> 训练数据：62,495 个零件，识别精度（F1）从规则方法的 53% 提升到 **83%**，是当前最优路线。

---

## 二、我们要解决的问题

CAD 零件里经常有**通槽**这种加工特征（你可以把它想象成一块金属板上挖穿过去的长方形凹槽）。工程师在做 CAE 仿真前，需要先在软件里把这些通槽"标出来"——以前是**人工标注**，一个零件几十分钟，全靠经验。

我们要做的是：**让 AI 自动识别并标出**。

**为什么难**？

| 难点 | 通俗解释 |
|---|---|
| 形状多样 | 通槽有矩形、圆弧、U 型、带圆角的……一个规则写不通用 |
| 易混淆 | 某些穿透结构（比如"穿透的长方孔""贯穿的圆角边"）外形上很像通槽，但**不是**通槽 |
| 数据稀缺 | 标注一个通槽很贵，不能让模型"看一眼就学会" |

**传统做法**：写一堆 if-else 规则（"如果一条边是凹的、且两面垂直、且面积比大于 X……"）—— 这种规则对长相规整的样本有效，对**真实工业零件**召回率/精度都不高。

## 三、数据从哪里来：NCTI 给我们的"零件体检报告"

我们用 **NCTI**（炎核 SDK，几何内核是开源的 OpenCASCADE）把 STEP 文件读进来。它对**每个面**和**每条边**都会生成一份"体检报告"，里面包含类型、面积、长度、凹凸性等 12 个数字。

### 3.1 每个面（Face）拿到什么

NCTI 给每个面一个 12 维向量 `FaceAttr[i]`，关键字段：

| 字段位置 | 含义 | 通俗解释 |
|---|---|---|
| `[0]` | 是不是平面 (PLANE) | 这面是不是平的？ |
| `[1]` | 是不是圆柱面 (CYL) | 这面是不是弯的圆柱？ |
| `[2]` | 是不是圆锥面 | 是不是锥形？ |
| `[3]` | 是不是球面 | 圆球？ |
| `[4]` | 是不是圆环面 (TORUS) | 圆环？ |
| `[5]` | 面积 | 这面多大（OCC 精确积分） |
| `[6]` | 是否 NURBS | 是不是用样条曲线画的？ |
| `[7]..[9]` | 归一化坐标 | 这面在零件里的"位置编码"（不是 3D 坐标，是 bbox 归一化值） |
| `[10]` | 环数 (loops) | 这面边界有几个独立圈 |
| `[11]` | 邻接面数 | 这面跟几面相邻 |

**注意**：NCTI 的体检报告里**没有** 3D 坐标和法向量——这些需要另外调用 `doc.GetNormalByUV()` / `doc.GetFacePointFromUV()` 在 UV 参数空间的中心点 (u=0.5, v=0.5) 采样得到。

### 3.2 每条边（Edge）拿到什么

`EdgeAttr[i]` 关键字段：

| 字段位置 | 含义 | 通俗解释 |
|---|---|---|
| `[0]` | 是不是凹边 | 两个面在这条边处形成**凹角**（内折） |
| `[1]` | 是不是凸边 | 形成**凸角**（外折） |
| `[2]` | 是不是光滑边 | 平滑过渡（无明显折角） |
| `[3]` | 边的长度 | 这条边多长 |
| `[4]` | 是不是圆弧边 | 弧线？ |
| `[9]` | 是不是直线边 | 直线？ |

**关键认知**：凹边/凸边的判断对识别通槽**至关重要**——通槽的内部边**几乎都是凹边**（挖下去的内折），这是最稳的判别信号。**这一步贡献了 62% 的模型判别力**。

### 3.3 拓扑结构：哪些边连着哪些面

NCTI 还给两个表：
- `FaceFID[i]` / `FaceEID[i]`：第 i 条边**连接的两个面的位置索引**
- 这就是"零件骨架图"——**面是节点，边是连线的图**（术语叫 AAG：Attribute Adjacency Graph）

## 四、整体路线：两级 AI 师傅

类比：
> 把识别通槽想象成"判断一块布上有没有开窗"。
> - **第一级师傅**看每条线（每条边），问"这条线像不像窗户的轮廓边？"
> - 把"是"的线连成一片（连通分量），形成"候选窗户区域"
> - **第二级师傅**看整片区域，问"这片区域是不是真的窗户（而不是形状相似的杂物）？"

### 4.1 端到端流程图

```
         ┌─────────────────────────────────────────────┐
         │  输入: 一个 STEP 文件                         │
         └───────────────────┬─────────────────────────┘
                             ↓
         ┌─────────────────────────────────────────────┐
         │  NCTI 导入（doc.New + RunCommand）             │
         │  → 拿到所有面的 FaceAttr + 所有边的 EdgeAttr    │
         │  → 拿到面邻接图（AAG）                          │
         └───────────────────┬─────────────────────────┘
                             ↓
         ┌─────────────────────────────────────────────┐
         │  NctiPart（NCTI 数据后端）                     │
         │  → 整理出 4 张边表：                          │
         │    邻接表 / 凸凹性 / 边长 / 边类型              │
         └───────────────────┬─────────────────────────┘
                             ↓
         ┌─────────────────────────────────────────────┐
   【一级】 build_face_graph(part)                      │
         │  → 遍历每对相邻面，算出 30 维边特征向量        │
         │  → XGBoost 边分类器预测 P(这条边在通槽内部)   │
         │  → 等温校准 → 剪枝（概率 ≥ 0.35 的留下）      │
         │  → 连通分量 = 候选通槽实例                    │
         └───────────────────┬─────────────────────────┘
                             ↓
         ┌─────────────────────────────────────────────┐
   【二级】 extract_instance_features(part, ...)         │
         │  → 对每个候选实例，算出 26 维整体特征          │
         │  → XGBoost 实例分类器预测 P(是真通槽)         │
         │  → P < 0.80 → 拒绝（剔除伪通槽）              │
         └───────────────────┬─────────────────────────┘
                             ↓
         ┌─────────────────────────────────────────────┐
         │  输出: list[实例]                              │
         │  每个实例 = {faces: [cell_id, ...],            │
         │             score, n_faces, inst_prob}        │
         │  faces 直接是 cell_id 位置索引                  │
         │  → 喂给后续的下游系统（高亮 / 清理 / 标注）    │
         └─────────────────────────────────────────────┘
```

## 五、第一级：30 维边特征详解

> 目的：**对零件图里的每一条边，回答"这是不是通槽内部的边？"**

### 5.1 30 个数字怎么分组

| 分组 | 数量 | 含义 |
|---|---|---|
| **边凸凹性** | 6 | 连续二面角符号 (+1=凹 / -1=凸 / 0=光滑) + 4 个 one-hot（凹/凸/光滑/未知） |
| **边几何** | 5 | 长度、归一化长度、类型 one-hot（直线/圆弧/其他） |
| **面面积** | 5 | 两面各自的面积 + 面积比 + log 面积比 |
| **面周长** | 3 | 两面各自的周长 + 周长比 |
| **面间几何** | 3 | 两面重心距离、法向夹角、法向点积 |
| **面类型 one-hot + 组合** | 8 | 3 个 A 类型 + 3 个 B 类型 + 3 个组合（都是平面/一平一圆/都是圆柱） |
| **合计** | **30** | |

### 5.2 为什么是这些数字？（设计逻辑）

| 特征 | 为什么选它 | 通俗解释 |
|---|---|---|
| **dihedral_sign**（最重要，占重要性 62%） | 通槽内部边**几乎都是凹的**，区分力最强 | 就像窗户的"内侧折角"——90% 的窗户边都是凹的 |
| **edge_length** + **归一化** | 通槽边一般较短且与零件总周长成比例 | 零件上特别长/特别短的边不太可能是通槽边 |
| **edge_is_circle** | 通槽的圆弧边是 U 型/带圆角通槽的强信号 | 圆弧边是"圆角通槽"的招牌 |
| **area_ratio** + **log** | 通槽底面 vs 壁面的面积比有特定模式 | 一个矩形窗户，底面窄、两壁面积差不多 |
| **normal_angle_deg** | 两面夹角（90° 是直角，0° 是平面） | 通槽底面和侧壁**几乎垂直**，这就是窗户的"墙角" |
| **face type one-hot** | 面类型组合（平面 vs 圆柱）能区分通槽的子类 | 矩形通槽是"平+平"，U 型通槽是"平+圆" |

### 5.3 怎么变成"候选实例"？

XGBoost 给每条边一个 0~1 的概率（这条边在通槽内部的把握）。然后：

1. **剪枝**：概率 < 0.35 的边丢掉（噪声）
2. **连通分量**：剩下的边按邻接关系聚团，**一团就是一个候选通槽**
3. **初步过滤**：团太小（<3 个面）或平面占比 < 50% 的丢掉

这一步**保证召回率**——宁可多留几个候选，也不能漏掉真的。

### 5.4 特征来源拆解（混合借鉴，非单一论文）

> ⚠️ **关键澄清**：30 维和 26 维特征**不是 FeatureFox 论文的精确复现**。

论文 ([_paper_text.txt:258-260](YHCADSmartCleaner/utils/through_step/featurefox_ncti/_paper_text.txt#L258-L260)) 只给了**大致类别名**：

> "Edge attributes include the **dihedral angle, concavity, area and perimeter ratios, normalized length and distance between face centroids and the edge class** among others."

并且论文 ([_paper_text.txt:103-104](YHCADSmartCleaner/utils/through_step/featurefox_ncti/_paper_text.txt#L103-L104)) 明确说：

> "Due to internal company policy and confidentiality constraints, we **cannot publicly release the code and data** for this work."

所以具体每一维怎么定义、怎么聚合，**论文没给、也给不了**。团队的特征设计是**混合借鉴 + 领域扩展**：

| 来源 | 贡献 | 30 维中的具体特征 |
|---|---|---|
| **FeatureFox 论文**（Fuchs et al. 2026, Siemens） | 两阶段框架 + 大类思路 | dihedral_sign / abs_dihedral / is_concave/is_convex/is_smooth / area_ratio / log_area_ratio / perim_ratio / edge_length_norm / centroid_dist / edge_is_circle 等 **~12 维** |
| **AAGNet 论文**（2024） | 面/边类型分类思路 | edge_is_line / edge_is_other / face_a_is_plane/cyl/other / face_b_is_plane/cyl/other 等 **~10 维** |
| **Joshi & Chang 经典论文**（1988） | AAG 凸凹性作为基础属性 | 概念性引用（不是单独的特征维度） |
| **团队自创** | 特征组合交互项 + 领域信号 | both_plane / plane_cyl / both_cyl / normal_angle_deg / normal_dot 等 **~5 维** |

**特征设计的总结说明**：

> 我们的特征设计**借鉴**FeatureFox 论文的两阶段框架和核心思路（凸凹性、面积比、归一化长度、面重心距），但**不是直接照抄**——因为论文本身不公开精确特征定义。具体 30 维边特征和 26 维实例特征是**结合 FeatureFox、AAGNet 和 1988 年 Joshi & Chang 经典文献，再加上领域经验综合设计**的。这种做法的好处：可以针对通槽这一类特征**做特化调整**（比如加入"底面-壁面垂直对数"这种领域信号），而论文的方法是面向 MFInstSeg 通用 24 类制造的，未必有这个特化。

**26 维实例特征也是同样情况**：

| 来源 | 贡献 | 26 维中的具体特征 |
|---|---|---|
| **FeatureFox 论文** ([_paper_text.txt:321-324](YHCADSmartCleaner/utils/through_step/featurefox_ncti/_paper_text.txt#L321-L324)) | 实例属性示例 | n_faces / n_edges / log characteristic length 共 **~3 维** |
| **团队设计** | 区分通槽 vs 同类伪通槽的领域信号 | 面积分布 / 周长分布 / 凹凸边占比 / 底壁结构 / 一级置信度 共 **~23 维** |

## 六、第二级：26 维实例特征详解

> 目的：**对第一级找到的每个候选团，问"这团是真通槽还是伪通槽？"**

### 6.1 为什么要第二级？

第一级的"冤假错案"里，**72% 是 seg=22** 这种和通槽长得一模一样的"穿透型结构"（比如穿透的长方孔、穿透的凹槽底面）。它们在**单条边**的几何上和通槽完全一样，第一级分不开。

只有**整体看**才能区分——所以用整实例的聚合特征做第二级。

### 6.2 26 个数字怎么分组

| 分组 | 数量 | 含义 |
|---|---|---|
| **规模** | 3 | 面数、内部共享边数、面/边比 |
| **面类型构成** | 5 | 平面数、圆柱数、其他数、平面占比、是否含圆柱壁 |
| **面积统计** | 6 | 总面积、最小、最大、均值、标准差、min/max 比、最小/总比 |
| **周长统计** | 3 | 总周长、平均周长、min/max 比 |
| **凹凸边构成** | 3 | 凹/凸/光滑 边占比 |
| **底壁结构** | 3 | 与底面近似垂直的壁面数、是否存在"1底+≥2壁"拆分、垂直对数均值 |
| **第一级置信度** | 2 | 该实例所有边的平均概率、最低概率 |
| **合计** | **26**（注：原文是 26 维，不是 24） |

### 6.3 关于"24 类"的说明

> 这里有个常见的说法差异需要澄清。

| 说法 | 实际含义 |
|---|---|
| "24 类" | 训练数据集标注的 `seg` 类别有 25 个（seg=0..24），其中 **seg=9 表示通槽**，其它 24 类是别的制造特征（圆角/倒角/各种孔等） |
| **26 维实例特征** | 是第二级分类器的输入向量长度（`INSTANCE_FEATURE_NAMES` 列表里有 26 个名字） |
| **第二级分类器输出** | 当前是**二分类**（"真通槽" vs "非通槽"），不是 24 分类 |

未来要做"panoptic 多类分割"时，第二级才会扩展为 24 类分类器输出 `seg=0..23`。

## 七、两级合起来的整体效果

### 7.1 在 62495 件测试集上的实测指标

| 指标 | 传统规则方法 | **本路线（两级）** | 提升 |
|---|---|---|---|
| **Precision（精准率）** | 45% | **85.7%** | +40.7 点 |
| **Recall（召回率）** | 63% | **81.3%** | +18.3 点 |
| **F1（综合）** | 53% | **83.4%** | **+30.4 点** |

**通俗解读**：原来模型"找 100 个里面只有 45 个是真的"；现在"找 100 个里有 86 个是真的"；原来"漏掉 37% 的真通槽"，现在"只漏掉 19%"。**整体综合性能提升超过一半**。

### 7.2 单级 vs 两级的差（为什么需要第二级）

| 指标 | 单级（只有边分类） | 两级（加实例分类） |
|---|---|---|
| Precision | 78.2% | **85.7%** |
| Recall | 80.8% | 81.3% |
| F1 | 79.5% | **83.4%** |
| FP 数 | ~410 | **~256** |

**通俗解读**：加第二级主要提升精度（少 38% 的误报），召回基本不变。**这就是为什么需要"两层确认"——一级把可疑的全圈出来，二级把"装得像的"剔除掉**。

## 八、训练数据是怎么准备的

| 数据集 | 数量 | 来源 |
|---|---|---|
| 训练集 | 62,495 个零件 | `D:\wyg\data\data\steps\` |
| 标签格式 | `seg` 字典 + `inst` 矩阵 + `bottom` 字典 | `D:\wyg\data\data\labels\` |
| 一级正样本 | 共享边两端面**同属一个通槽实例** | seg=9 且 inst=1 的边 |
| 二级正样本 | 整组面都是 seg=9 | 真通槽实例 |
| 二级负样本 | 整组面 seg≠9 且 ≠0 | 其它制造特征（含 seg=22 装得像的） |

**关键设计决策**：二级分类器**不**用真实 inst 矩阵分组做训练样本——而是**用第一级剪枝出来的连通分量**做样本。这保证训练和服务一致（业界论文里的常见教训：训练用"上帝视角"，服务用"模型视角"，分布不一致就废）。

## 九、和"STEP 版"的关系（为什么要重写一套）

`featurefox_ncti` 是 `featurefox`（STEP 版）的升级版，两者**平行、不混合**。

| 维度 | STEP 版 | **NCTI 版（本路线）** |
|---|---|---|
| 数据源 | 解析 STEP 文本 | 直接用 NCTI AiModel |
| 凸凹性 | 质心偏移法反推（连续值） | **EdgeAttr[0/1/2] 直接给（更准）** |
| 面积/边长 | 从 STEP 文本近似算 | **NCTI 精确积分** |
| 输出面号 | STEP face_id → **需几何最近邻映射** | **cell_id 位置索引，零映射** |

**零映射是关键**：少了一次"猜哪个 STEP 面是哪个 NCTI 面"的步骤，避免了曲面特征（圆角/锥面/自由曲面）映射不可靠的老大难问题。

**代价**：本路线训练+推理都依赖 NCTI SDK + Python 3.12 环境（不能像 STEP 版那样纯 Python 跑）。

### ⚠️ 当前限制
- 只识别"通槽"单类（seg=9）；其它 24 类要扩展第二级为多分类
- 训练数据是**合成件**（OCC 生成的），真实工业件上**可能**因 OCC 共面合并导致面数不匹配而跳过
- 批量训练需数小时（subprocess 隔离解决 NCTI C++ 累积 segfault）

### 🚀 未来路线
1. **多类扩展**：把第二级从二分类扩成 25 分类，输出 `seg=0..24`
2. **真实件适配**：真实工业件的 cell_id 对齐、面数断言优化
3. **跨特征迁移**：把"两级"框架迁移到盲孔、倒角、圆角等其他制造特征

## 十一、5 分钟摘要

> 我们要识别 CAD 零件里的通槽。以前写规则，识别率 53%。
>
> 现在用 AI 模型，分两级：
> - 第一级看每条边，30 个数字描述它的形状和位置，问"这条边是不是通槽边"；
> - 把可疑的边连成片，第二级看整片区域，26 个数字描述整体，问"这片是不是真通槽"。
>
> 数据是 NCTI 给出的零件体检报告——每个面 12 个数字、每条边 10 个数字。
>
> 训练用了 6 万多个零件。最终识别率从 53% 提到 83%，误报少了一半多。
>
> 现在已经集成到 GUI 里了。下一步要把这个框架扩展到其他类型的特征（盲孔、倒角等）。
